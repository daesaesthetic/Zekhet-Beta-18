Upgrade the existing ⛤ Zekhet ⛤ Discord bot by interconnecting the systems that already exist.

IMPORTANT:
Zekhet is already functional and stable.

This is NOT a rebuild.

Do NOT replace, redesign, or unnecessarily refactor existing systems.

The goal of this task is to make existing actions naturally affect other existing systems.

Current systems include:

- Profile / Record
- Titles / Court
- Lore / Archives
- Curses / Rituals
- Contracts / Ledger
- Achievements
- Tutorial / Tuto
- Developer Console
- Custom server prefix

Do NOT add the Passport yet.
Do NOT add Familiarity yet.
Do NOT add a new economy.
Do NOT add AI.
Do NOT add a web dashboard.

==================================================
1. CORE CONCEPT
==================================================

Create connections between existing systems.

The user should feel that actions have consequences beyond the command they just used.

Examples:

Completing a contract
→ may unlock an achievement

Discovering certain lore
→ may unlock a title

Receiving a curse
→ may unlock an achievement

Obtaining an achievement
→ may grant a title

Completing tutorial objectives
→ may unlock existing titles, lore, or achievements

Owning certain combinations of titles/lore/achievements
→ may unlock special content

The systems should feel like one interconnected progression system rather than separate features.

==================================================
2. EXISTING SYSTEMS MUST REMAIN INTACT
==================================================

Do not change existing command names or behavior unless necessary.

Do not remove existing content.

Do not reset existing user progress.

Do not restructure the database unnecessarily.

Reuse existing database tables, functions, and event handlers wherever possible.

If the current architecture already has a suitable event/callback system, use it.

If not, create lightweight helper functions for progression events.

==================================================
15. DUPLICATE PREVENTION
==================================================

This is extremely important.

Rewards must never duplicate incorrectly.

If a user already owns a title:

Do not grant a second copy.

If a user already unlocked an achievement:

Do not unlock it again.

If a lore entry is already discovered:

Do not create a duplicate.

If a progression event happens multiple times:

The associated one-time reward should only trigger once.

Make all progression checks idempotent.

==================================================
16. EXISTING USERS
==================================================

Do NOT reset existing users.

Existing users should retain:

- Titles
- Lore
- Curses
- Contracts
- Achievements
- Tutorial progress
- Profile information

Where possible, existing data should naturally satisfy progression requirements.

For example:

If a user already owns 15 titles when this update is installed, the achievement for owning 10 titles should be eligible to unlock.

Do not require them to collect 10 additional titles.

==================================================
17. DATABASE SAFETY
==================================================

Only add tables/columns if genuinely necessary.

Do not migrate or rebuild the entire database unnecessarily.

Ensure the bot can restart without losing progression.
