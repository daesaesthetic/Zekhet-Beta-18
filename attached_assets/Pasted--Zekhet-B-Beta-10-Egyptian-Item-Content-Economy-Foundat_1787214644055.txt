# Zekhet-B Beta 10 — Egyptian Item Content & Economy Foundation

We are continuing development of Zekhet-B.

The current codebase is at Beta 9 and the existing systems are functioning correctly.

The following systems are currently confirmed to exist:

* Tuto system
* Tuto objectives
* Tuto progression/unlocks
* Item definitions
* User inventories
* Item persistence
* Existing reward functionality

Important: **Do not assume that XP, levels, ranks, or currency/economy systems currently exist.** They were discussed in previous development planning, but they are not currently implemented in the codebase.

This update should establish the foundation for Zekhet-B's economy while also populating the existing inventory with initial items that fit the game's mystical/ancient Egyptian identity.

Do NOT rebuild existing systems.

---

## PART 1 — Currency System

Create a persistent Zekhet-B currency system.

The currency should have a unique name that fits the game's ancient Egyptian/mystical theme rather than simply being called "coins" or "currency."

Use an appropriate name such as **Khepri**, **Deben**, **Gold**, or another fitting term if the existing project already has a better naming convention.

If a currency name is already defined elsewhere in the project, use that instead of creating a second currency.

### Currency Requirements

Create a centralized currency service capable of:

* Getting a user's balance
* Adding currency
* Removing currency
* Checking whether a user has enough currency
* Setting a balance when necessary
* Preventing negative balances
* Persisting balances
* Safely handling invalid transactions

Use the project's existing database/user-data architecture.

Do NOT create a separate database solely for currency if the existing architecture can support it.

### Data Integrity

The currency system must:

* Persist through bot restarts
* Never generate negative balances
* Never silently lose currency
* Avoid duplicate transactions
* Validate transaction amounts
* Fail safely if a transaction cannot be completed

Create reusable internal functions/services so future commands can interact with currency without duplicating logic.

Populate the existing item system with an initial collection of Zekhet-B-themed items.

The items should feel like mysterious artifacts, relics, materials, and treasures discovered throughout an ancient mystical world.

Do NOT make every item a direct copy of a real Egyptian artifact.

The goal is to create an original Zekhet-B identity inspired by ancient Egyptian mythology, symbolism, temples, deserts, gods, scribes, tombs, and the Nile.

## Important Item Design Rules

Do not give every item a gameplay effect yet.

Some items should exist primarily as:

* Collectibles
* Materials
* Relics
* Quest objects
* Rare discoveries

This gives us room to later build:

* Item effects
* Crafting
* Quests
* Collections
* Shops
* Loot tables
* Events
* Trading
* Achievement requirements

Do not implement those systems yet unless they already exist.

# PART 3 — Item Values

Where the current item architecture supports it, add a standardized value/economic metadata field to items.

This should allow future systems to determine an item's economic value without hardcoding individual item prices.

Do NOT automatically create a shop.

Do NOT make every item purchasable.

Some rare items should intentionally have no current economic use.

---

# PART 4 — Currency + Item Rewards

Integrate the new currency system with the existing reward infrastructure where appropriate.

Existing systems should be able to award:

* Currency
* Items
* Both simultaneously

For example, an existing objective could eventually reward:

> ✦ Objective Complete
>
> `+250` Deben
> `+1 Papyrus Fragment`

However, do not rewrite the entire reward system into the future unified reward architecture yet.

The goal of this beta is simply to establish reliable currency and item reward compatibility.
