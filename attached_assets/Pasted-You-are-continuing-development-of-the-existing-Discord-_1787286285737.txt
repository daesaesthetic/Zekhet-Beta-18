==================================================
PART 1 — REDUCE VENTURE COOLDOWN
==================================================

The current /venture cooldown is approximately 15 minutes.

Change the standard Venture cooldown to:

5 MINUTES

Do not remove the cooldown.

Do not make Venture unlimited.

Do not create a new cooldown architecture if the existing cooldown system can be reused.

The existing effect system already supports cooldown-related modifiers.

Preserve compatibility with:

- COOLDOWN_REDUCTION
- Other existing effects
- Existing cooldown persistence
- Existing cooldown reset/developer functionality

The resulting behavior should be:

NORMAL:
5 minute Venture cooldown

WITH COOLDOWN REDUCTION:
Existing effect calculations continue to modify the cooldown appropriately.

Do not hard-code a separate cooldown calculation that bypasses the existing effect system.

==================================================
PART 2 — ADD /SCAVENGE
==================================================

Add a new gameplay command:

/scavenge

Also add the appropriate prefix equivalent if Zekhet's existing command architecture supports prefix equivalents.

The purpose of Scavenge is:

"Search the area around you for small discoveries, items, currency, or clues."

Scavenge should NOT simply be a second copy of Venture.

It should be a SHORT-CYCLE activity.

Recommended cooldown:

2 MINUTES

Use the existing cooldown infrastructure rather than creating a completely separate cooldown system.

==================================================
SCAVENGE DESIGN
==================================================

Scavenge should produce a smaller, faster outcome than Venture.

Possible outcomes include:

- Small Deben reward
- XP
- Common item
- Uncommon item
- Rare item with a low probability
- Flavor-only discovery
- Clue
- Minor progression event

The reward should generally be smaller than Venture.

Example:

⛤ SCAVENGE ⛤

You search the remains of an abandoned courtyard.

Among the dust, you discover:

🪙 Ancient Coin ×2
+18 Deben

or:

⛤ SCAVENGE ⛤

You sift through the sand beneath a broken statue.

You find nothing of value.

But something catches your eye...

📜 A strange symbol has been carved into the stone.

Do NOT create dozens of new database tables for Scavenge.

Reuse the existing:

- Item catalog
- Inventory
- Reward system
- XP system
- Deben system
- Effect system
- Progression system

where appropriate.

==================================================
SCAVENGE AND EXISTING EFFECTS
==================================================

Scavenge should respect relevant existing effects where appropriate.

For example:

ITEM_FIND_BOOST

LUCK_BOOST

DEBEN_BOOST

XP_BOOST

Do not invent new effect types for this Beta.

Use the existing effect calculation architecture.

If an existing effect is specifically designed only for Venture and cannot safely apply to Scavenge, leave it unchanged and document the limitation rather than rewriting the effect system.

==================================================
SCAVENGE REWARD BALANCE
==================================================

Scavenge is intended to be:

SHORTER
SMALLER
MORE FREQUENT

than Venture.

Avoid making Scavenge more profitable than Venture.

A player should still want to use Venture.

Think of the distinction as:

VENTURE:
Major expedition.
Higher rewards.
Longer cooldown.

SCAVENGE:
Quick search.
Smaller rewards.
Shorter cooldown.

PART 3 — ADD /INSPECT
==================================================

Add:

/inspect

and the appropriate prefix equivalent if supported by the existing architecture.

Inspect should be fundamentally different from Venture and Scavenge.

Its purpose is:

"Examine your surroundings and potentially notice something unusual."

Inspect should be primarily discovery/flavor focused.

Possible outcomes:

- Flavor text
- Clue
- Lore discovery if appropriate
- Rare observation
- Hint toward another system
- Small XP reward
- Very small Deben reward
- Nothing

Inspect should NOT become a major reward generator.

The primary reward is:

CURIOSITY.

==================================================
INSPECT EXAMPLES
==================================================

Example 1:

⛤ INSPECTION ⛤

You examine the cracked wall beside you.

At first, there is nothing unusual.

Then you notice a phrase carved beneath the dust:

"The king did not die here."

📜 Something about this place feels familiar.

Example 2:

⛤ INSPECTION ⛤

You inspect the remains of an ancient doorway.

The stone is cold.

Nothing appears to have changed...

But you swear the symbols weren't facing this direction before.

Example 3:

⛤ INSPECTION ⛤

You search the area carefully.

You find nothing unusual.

Example 4:

⛤ INSPECTION ⛤

You discover a faint inscription hidden beneath the sand.

📜 Lore discovered:
[Existing lore entry]

If an existing Lore entry is discovered, use the existing Lore catalog and persistence system.

Do NOT create a duplicate lore system.

==================================================
INSPECT COOLDOWN
==================================================

Inspect should have a SHORT cooldown.

Recommended:

30 SECONDS

This should prevent spam while allowing it to function as a quick exploratory action.

Reuse the existing cooldown architecture.

Do not create a separate cooldown implementation.

- 2 minute cooldown

"Look closer."

- Discovery/flavor activity
- 30 second cooldown

- Occasional clues
- Possible lore discovery
- Minimal economic rewards

Do NOT make all three commands feel like the same RNG system with different names.
