You are continuing development of the existing ⛤ Zekhet ⛤ Discord bot.

CURRENT VERSION:
Zekhet-Beta-17

Beta-17 successfully connected Venture with the Inventory system.

Now begin:

⛤ ZEKHET-BETA-18 ⛤
THE RELIC & EFFECT SYSTEM

==================================================
CORE OBJECTIVE
==================================================

Turn selected inventory items into usable gameplay tools.

The intended loop is:

/venture
↓
Discover item
↓
/inventory
↓
/use item:<item>
↓
Temporary effect
↓
Effect modifies future gameplay
↓
Effect expires
↓
Continue venturing

The goal is to make items feel useful rather than purely collectible.

IMPORTANT:

Keep this phase focused.

Do not implement the Bazaar.

Do not implement trading.

Do not implement crafting.

Do not implement Contracts integration.

Do not implement full Lore integration.

Do not rebuild Venture.

Do not rebuild Inventory.

Reuse existing systems wherever possible.

==================================================
1. /USE COMMAND
==================================================

Implement:

/use item:<item>

Also support the existing configurable prefix system:

z!use <item>

The command must only work with items that are explicitly marked as usable.

Example:

/use item:Lucky Scarab

Possible response:

⛤ ITEM USED ⛤

🪲 Lucky Scarab

The markings begin to glow.

🍀 Luck +100%

Duration:
2 hours

The item has been consumed.

==================================================
4. EFFECT SYSTEM
==================================================

Create a lightweight reusable temporary-effect system.

An active effect should support:

- Unique effect ID
- Effect type
- Magnitude
- Start time
- Expiration time
- Source item
- Optional stacking behavior

The system should be reusable by future features.

Do not create separate hard-coded logic for every item.

For example:

LUCK_BOOST
DEBEN_BOOST
XP_BOOST
COOLDOWN_REDUCTION
RARE_ENCOUNTER_BOOST
ITEM_FIND_BOOST

The effect system should allow future effects to be added without rewriting /use.

==================================================
5. EFFECT EXPIRATION
==================================================

Effects must expire automatically based on time.

Do not require a background process.

Determine whether an effect is active when it is relevant.

For example:

User activates Lucky Scarab at:

12:00 PM

Duration:

2 hours

At:

2:01 PM

the effect should be treated as expired.

Expired effects should no longer influence gameplay.

Clean up expired effects when practical.

==================================================
7. INVENTORY INTEGRATION
==================================================

When a usable item is successfully activated:

1. Verify the user owns the item.
2. Verify the item is usable.
3. Remove ONE quantity from the inventory.
4. Create or update the appropriate temporary effect.
5. Display the effect.
6. Display the duration.
7. Confirm the item was consumed.

If the user has:

Lucky Scarab ×3

and uses one:

Lucky Scarab ×2

should remain.

==================================================
8. INVALID USE CASES
==================================================

Handle these gracefully.

If the user does not own the item:

"You do not possess that item."

If the item exists but is not usable:

"That item cannot be used."

If the item name is invalid:

"Zekhet cannot identify that item."

If the item is already providing an active effect:

Determine the stacking rule and explain it clearly.

Do not produce database errors or generic bot errors.

==================================================
9. EFFECT STACKING
==================================================

Implement conservative stacking rules.

By default:

The same effect should NOT stack infinitely.

For example:

Using Lucky Scarab while Lucky +100% is already active should not produce:

+200%
+300%
+400%

Instead, use a simple rule.

Recommended behavior:

If the same effect is already active:

Extend the duration rather than infinitely increasing the magnitude.

Example:

Lucky +100%
1 hour remaining

Use another Lucky Scarab:

Lucky +100%
3 hours remaining

OR, if simpler:

Do not allow the second use and explain that the effect is already active.

Choose whichever is cleaner for the existing architecture.

Document the decision.

Different effects should be allowed to coexist.

Example:

Lucky +100%
Deben +25%
XP +25%

==================================================
10. LUCK SYSTEM
==================================================

Implement a reusable luck modifier.

Do NOT interpret luck as simply multiplying every reward.

Luck should primarily influence randomized outcomes.

For Beta-18, allow Luck to influence:

- Encounter rarity
- Item discovery probability

Do not make Luck guarantee rare encounters.

Example:

Normal:

Common encounter:
60%

With Lucky effect:

Common:
slightly reduced

Uncommon:
slightly increased

Rare:
noticeably increased

Epic+:
still rare

Keep the effect controlled.

A player using Lucky Scarab should feel more fortunate, not invincible.

13. COOLDOWN REDUCTION
==================================================

Implement:

COOLDOWN_REDUCTION

This effect should modify the existing Venture cooldown.

Example:

Normal cooldown:
15 minutes

Effect:
-25%

Effective cooldown:
11 minutes 15 seconds

Do not permanently change the user's normal cooldown.

Only modify the current Venture cooldown calculation while the effect is active.

Do not allow cooldown reduction to reach zero.

Set a reasonable minimum cooldown.

==================================================
14. RARE ENCOUNTER BOOST
==================================================

Implement:

RARE_ENCOUNTER_BOOST

This should influence Venture encounter rarity.

Do not guarantee Rare/Epic/Legendary encounters.

The effect should increase the probability of higher rarity.

The exact multiplier should be conservative.

Document the probability calculation.

==================================================
15. ITEM FIND BOOST
==================================================

Implement:

ITEM_FIND_BOOST

This should increase the chance of receiving an item from Venture.

Again:

Do not guarantee an item.

Do not make every Venture produce an item.

The effect should modify the existing item discovery probability.

==================================================
BETA-18 SUCCESS CRITERIA
==================================================

Beta-18 is successful when a user can:

1. Discover a usable item through /venture.
2. View it in /inventory.
3. Use it with /use item:<item>.
4. Receive a temporary advantage.
5. See that advantage through /effects.
6. Run /venture again and notice that the effect actually matters.
7. Wait for the effect to expire.
8. Return to normal gameplay.

The user should feel:

"I found something during my adventure that actually changes how I play."

Do not over-engineer the system.

Keep it modular, stable, understandable, and credit-efficient.
